# Canary credential incident closure

Status: `MITIGATED_WITH_RESIDUAL_RISK`.

Closed controls:

- The active canary password is stored only in the isolated Railway staging environment.
- No provider credential exists in staging variables or in `ai_provider_keys` for the synthetic tenant.
- The password was passed directly from Railway into browser memory and was not printed or written to an evidence file.
- Browser logout was observed and both browser sessions were finalized.
- The browser automation runtime was reset after use.
- Root and frontend `.env.local` files generated by Vercel linking were removed.
- The generated frontend build directory was removed after validation because Next.js creates ephemeral preview/signing/encryption keys in build output.
- Evidence and JUnit directories scanned clean, except two `graph_key` false positives in an older staging evidence JSON.
- The remediation commit range produced one false positive: a Railway service ID.

Residual risk:

- A full Git-history scan found `38` detector hits. `35` are documented IDs, graph keys, fixtures, examples or redacted curl placeholders.
- Three high-entropy development values (`JWT_SECRET`, `ENCRYPTION_KEY`, `DEBUG_COLLECT_TOKEN`) existed in `.replit` at commit `205a64d23eb66e2f5456cd7e284c2a0b03a1ed1a` and were absent in the immediately following commit `24cd1622ac98dd096b2ff9ac530e1e21aad8ce8d`.
- The values remain recoverable from Git history and no authoritative external revocation/rotation record was available in this run.

Required closure before production acceptance: confirm those three historical development values are revoked or rotated in every system where they may have been used, then retain the external audit proof. The values themselves are not reproduced in this report.
